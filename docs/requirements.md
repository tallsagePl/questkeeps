# QuestKeeps: восстановленные требования v1.1

Источник: сообщения пользователя в беседе «Приложения для путешествий» и текущая задача. Это фиксация доступных решений, а не дословная копия недоступного ответа с ТЗ.

## Подтверждённые решения

Продукт для себя и друзей. Регистрация по email и через Яндекс. Поездки создаются вручную; приложение обрабатывает выбранные папки, а не весь архив и не создаёт другие поездки автоматически.

К поездке можно подключать выбранные папки нескольких аккаунтов Яндекс Диска, в том числе папки других участников. Источник участника одобряет владелец поездки. Пользователь публикует собственные материалы из своих аккаунтов; нельзя подключить аккаунт другого пользователя через API.

Владелец приглашает участников на включительный период внутри поездки. Даты ограничивают и чтение, и добавление записей/материалов. После выхода фотографии остаются; автор может скрыть свои. Другие участники не могут скрывать чужие файлы. Владелец управляет источниками и участием.

Фото и видео индексируются сразу, автоматически публикуются в одобренной поездке. Оригиналы остаются в облаке, доступны просмотр и скачивание. Поддерживаемые браузером форматы видео воспроизводятся, остальные скачиваются.

Есть периодическая синхронизация и кнопка ручного обновления источника. Новые и удалённые файлы отражаются в индексе. Места предлагаются по GPS с подтверждением; показывается краткое описание с указанием источника.

Минималистичный интерфейс, крупные кадры и карта. Просмотр поездки без аккаунта доступен исключительно по секретной ссылке. Ссылка не даёт прав редактирования и может быть отозвана.

## Реализованные экраны

Вход и регистрация; коллекция поездок; создание поездки; галерея и просмотр кадра; карта; дневник; участники и периоды; приглашение; подключение и одобрение папок; выбор папки своего аккаунта; профиль с управлением видимостью своих файлов; гостевая поездка.

## Принятые технические решения

Next.js App Router, React, TypeScript, SQLite / better-sqlite3, bcrypt, AES-256-GCM для OAuth-токенов, opaque-сессии HttpOnly. Leaflet / OpenStreetMap; Wikipedia geosearch + вводные абзацы с атрибуцией. Локальный Node-процесс для фоновой синхронизации. Миниатюры запрашиваются у Диска, локальные копии изображений не сохраняются.

Лимит одного прохода: 2000 страниц по 100 ресурсов или 15 минут. Источник рекомендуется ограничивать одной поездкой. Автоматическая синхронизация каждые 15 минут; смена периода участника меняет доступ сразу и учитывается при следующем проходе его источников. Удаление/переименование на Диске отражается после успешного сканирования. Ошибки не удаляют прошлый индекс.

Нет автоматического слияния пользователей по email Яндекса: для привязки нужно войти в существующий аккаунт и подключить Яндекс через профиль. Это предотвращает захват локального аккаунта через совпавший email.

## Практические ограничения этой версии

Реальный OAuth требует ключей владельца приложения. Автоматический GPS читается из JPEG; для остальных форматов доступны метаданные Диска и ручные координаты. Не реализованы восстановление пароля по email, подтверждение email, перекодирование видео, правка даты съёмки, фоновая очередь для очень больших библиотек и production-мониторинг. Приложение рассчитано на небольшой доверенный круг, один Node-хост и постоянный диск; проверка чужого авторства внутри своего Диска технически не выполняется.

Гостевая ссылка открывает всю опубликованную поездку, поэтому ограниченный по датам участник, отдельно получивший эту ссылку, получает возможности гостя. Это соответствует явному разрешению просмотра всем обладателям ссылки.
