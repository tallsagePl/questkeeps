# Translations

Interface copy lives in `lib/i18n/ru.json` and `lib/i18n/en.json`. Both files use the same stable keys and parameter names.

```tsx
const { t, m } = useLocale();

t('common.save');
t('validation.minLength', { count: 6 });
m({ key: 'validation.minLength', params: { count: 12 } });
```

`t` accepts only keys known to TypeScript. Prefer semantic names such as `auth.signIn`. Templates use named parameters (`{count}`, `{date}`); missing keys or parameters fail explicitly.

`m` renders an application key, a `{ key, params }` descriptor or an unchanged plain string. Store descriptors in validation, notice and inference state so they follow a language change. Render user names, trip titles, journal text and filenames directly, without translation helpers.

Outside React use `translate(key, language, params)`. `translateCurrent` is for imperative browser integrations; inside a component use `useLocale`.

## Server messages

Pass a key or descriptor to `fail` / `HttpError`. For example:

```ts
fail(403, 'messages.accessDenied');
fail(502, { key: 'errors.yandexUnavailable', params: { status: 503 } });
```

`lib/i18n/messages.ts` normalizes only the application fields `error`, `message`, `fieldErrors`, `warnings`, and source errors. Readable Russian fields remain available for existing API consumers, with explicit descriptors in the corresponding translation metadata. Unknown provider text stays verbatim. Neither language is used as a lookup table for arbitrary prose.

Sync stores application keys in `sources.error`; parameterized messages use `storeMessage` and are decoded only at the source-message boundary. Migration 004 contains a frozen mapping for older sync errors. Do not expand runtime normalization to user content or geographic geometry.

The API client keeps descriptors intact. `ApiError.applicationMessage` is used by feedback; the standard `Error.message` retains a key for static messages and readable fallback text for older callers. New feedback code should retain the descriptor rather than formatting it before storing state.

`tests/i18n.test.ts`, `tests/refactor-boundaries.test.ts` and `tests/client-api.test.ts` check parity, interpolation, storage and response boundaries. `e2e/i18n.spec.ts` verifies stored errors and OAuth copy in both languages, including server parameters after switching language.
