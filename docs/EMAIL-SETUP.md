# Подтверждение почты QuestKeeps

В приложении подготовлена отправка через Resend. Наличие домена сайта само по себе не включает доставку: нужны подтверждённый домен отправителя, ключ сервиса и включённая проверка регистрации.

## Resend и Cloudflare

1. Создайте аккаунт https://resend.com/signup и откройте https://resend.com/domains.
2. Добавьте домен `mail.questkeeps.ru`. Отправитель: `QuestKeeps <noreply@mail.questkeeps.ru>`.
3. Добавьте в Cloudflare DNS-записи с точными именами, типами, приоритетами и значениями из Resend. Не подставляйте чужие DKIM-ключи или примерные значения. Если мастер предлагает автоматическое подключение Cloudflare, проверьте список добавляемых записей.
4. Существующие A/AAAA, NS и записи приёма почты сайта сохраняются. Для одного имени не создавайте две SPF-записи. DNS-записи почты не должны проходить через HTTP-прокси Cloudflare.
5. В Resend запустите проверку и дождитесь статуса `Verified`. Для писем подтверждения отключите отслеживание открытий и переходов.
6. На https://resend.com/api-keys создайте ключ с разрешением отправки только для `mail.questkeeps.ru`.

Официальные инструкции: https://resend.com/docs/dashboard/domains/introduction и https://resend.com/docs/dashboard/api-keys/introduction. Конкретные DNS-записи выдаёт аккаунт Resend.

## Приватная конфигурация

В `.env.local` соответствующего окружения задайте:

```dotenv
RESEND_API_KEY=YOUR_PRIVATE_SENDING_KEY
EMAIL_FROM=QuestKeeps <noreply@mail.questkeeps.ru>
EMAIL_VERIFICATION_REQUIRED=false
```

Для production также нужен `APP_URL=https://questkeeps.ru`. Локальный `APP_URL=http://localhost:3000` сохраняется для локальной разработки. Письма содержат ссылку именно на APP_URL окружения, где была создана регистрация.

Ключ хранится только в приватном `.env.local`, на VPS — с правами 600. Он не должен попадать в Git, клиентские переменные NEXT_PUBLIC_* или журналы. После изменения окружения перезапустите сервис: web и worker должны читать одинаковую конфигурацию.

## Проверка и включение

1. Выполните `npm run health`: база исправна, `mailTransportConfigured=true`. Этот признак проверяет наличие настроек, а не доставку письма.
2. Отправьте тест на свой адрес: `npm run mail:test -- your-address@example.com`. Успех команды означает принятие письма Resend; проверьте доставку во входящие и спам.
3. После успешной доставки включите `EMAIL_VERIFICATION_REQUIRED=true` и перезапустите сервис.
4. Зарегистрируйте новый тестовый аккаунт: до подтверждения вход по паролю закрыт, ссылка приходит на почту, подтверждается кнопкой и после использования становится недействительной. Проверьте повторную отправку.
5. Просмотрите журнал worker и `npm run health`: незавершённые задания не накапливаются, `emailQueue.exhausted=0`.

Письма обрабатываются отдельным циклом каждые 5 секунд и не ждут завершения синхронизации Диска. Не запускайте второй worker при использовании `npm run dev`, `npm start` или стандартного systemd-сервиса: supervisor уже запускает его.

У существующих пользователей настройки подтверждения автоматически не меняются. Если провайдер отклоняет отправку, очередь повторяет доставку с паузами; требуется исправить ключ/домен и проверить очередь. Не включайте обязательное подтверждение до реальной проверки доставки.

## Оформление писем и аватар отправителя

Шаблон содержит встроенный PNG-логотип (CID), кнопку подтверждения, обычный текст и футер со ссылками на сайт. Русский/английский язык берётся из регистрации или повторной отправки и сохраняется в зашифрованном задании очереди. Для добавления действующего Telegram-бота в футер задайте `EMAIL_SUPPORT_URL=https://t.me/REAL_BOT_HANDLE` и перезапустите сервис. До появления реального контакта ссылка не выводится.

`npm run mail:test -- address@example.com` отправляет оформленное тестовое письмо с кнопкой сайта, без фиктивного подтверждающего токена.

Логотип внутри письма не является аватаром Gmail. Для аватара Gmail требует сертификат CMC/VMC и DMARC; одной настройки Resend недостаточно. Подготовлены `public/brand/questkeeps-avatar.png` (1024×1024) и SVG `public/brand/questkeeps-bimi.svg`. SVG ещё должен пройти проверку выбранного удостоверяющего центра. BIMI-записи не публиковались: сначала нужны сертификат, подходящая политика DMARC и доступность файлов по HTTPS после развёртывания.

Требования Google: https://knowledge.workspace.google.com/admin/security/set-up-bimi. Покупка сертификата и проверка бренда выполняются отдельно; без них нельзя обещать показ аватара в Gmail.
