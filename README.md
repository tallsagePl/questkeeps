# QuestKeeps

![QuestKeeps](public/brand/questkeeps-blue.svg)

Личный архив путешествий на Next.js / TypeScript. Фото и видео остаются на Яндекс Диске; в SQLite сохраняются метаданные, участники, записи и места.

## Запуск

Требуется Node.js 22.19+ и npm. В этой папке зависимости установлены, локальный ключ шифрования уже создан в .env.local.

```powershell
cd C:\Users\tallsage\Documents\code_parade\travel
npm run dev
```

Откройте http://localhost:3000. Команда запускает сайт и отдельный процесс синхронизации с периодом 15 минут. Остановка — Ctrl+C. Можно сразу зарегистрироваться по email, создать поездку, написать историю и проверить гостевую ссылку.

Для повторной установки: npm ci. На новом компьютере скопируйте .env.example в .env.local и создайте TOKEN_ENCRYPTION_KEY (32 случайных байта в hex) и CRON_SECRET. Никогда не публикуйте .env.local или data/.

## Подключение Яндекс ID и Диска

1. Создайте своё приложение в https://oauth.yandex.ru/ .
2. Укажите веб-платформу, Redirect URI: http://localhost:3000/api/auth/callback .
3. Разрешения: login:info, login:email, login:avatar, cloud_api:disk.read. В настройках Яндекса включите «Доступ к портрету пользователя» (login:avatar). Приложение запрашивает аватарку как необязательное разрешение: отказ не мешает подключить Диск. Для уже подключённого аккаунта повторите подключение и разрешите доступ к портрету. Доступ на запись не используется.
4. Внесите идентификатор и секрет в YANDEX_CLIENT_ID и YANDEX_CLIENT_SECRET в .env.local. Перезапустите npm run dev.
5. Войдите в QuestKeeps. Откройте профиль → «Подключить аккаунт Яндекса» или «Участники и Диски» → «Подключить папку». Можно подключить несколько своих аккаунтов.
6. Выберите именно папку поездки, а не весь Диск. Владелец подключает свою папку сразу. Папка другого участника ожидает одобрения владельца. После одобрения нажмите значок синхронизации или дождитесь автоматического прохода.

Яндекс выдаёт OAuth-доступ на чтение Диска целиком, а не разрешение на одну произвольную папку. Ограничение индексирования выбранной папкой реализовано на сервере QuestKeeps. Обход других папок и автоматическое обнаружение других путешествий не выполняются. Выбор папок в интерфейсе показывает их названия в вашем аккаунте, индексирование начинается только после подключения.

Реальная авторизация и файлы пользователя не проверялись: ключи Яндекс OAuth не предоставлены. В тестах ответы внешних сервисов заменены контролируемыми данными.

## Возможности MVP

- Редактирование никнейма и собственной аватарки в профиле. Фото JPG/PNG/WebP до 5 МБ преобразуется в WebP 512×512 без метаданных и хранится в SQLite. Своя аватарка имеет приоритет в профиле; карточка Диска показывает аватарку Яндекса.

- Регистрация и вход по email/паролю; вход с Яндекс ID после настройки ключей. Пароли bcrypt, сессии HttpOnly, SameSite=Lax; токены сессий и ссылок хешируются.
- Несколько поездок, создаваемых вручную. Владелец и участники; одноразовые приглашения на 7 дней с ограничением по датам. Владелец может менять период и завершать участие.
- Серверное ограничение чтения фотографий, видео, записей и мест периодом участия. Проверка применяется также к миниатюрам, оригиналам и скачиванию.
- Фотографии публикуются из одобренного источника автоматически. Скрыть или показать кадр может только его автор. После выхода опубликованные кадры остаются; скрывать их можно через профиль. Синхронизация папок вышедшего участника приостанавливается.
- Один подключённый Яндекс-аккаунт на пользователя; участники подключают собственные Диски. Отключение в профиле удаляет токены и приостанавливает синхронизацию, сохраняя поездки и индекс. Выбранные папки, пагинация и рекурсивный обход. Повторный проход не дублирует кадры; удалённые с Диска файлы отмечаются недоступными только после успешного полного сканирования. Сбой не очищает существующий индекс.
- Ручная и периодическая синхронизация, блокировка одновременных проходов, статус и текст ошибки.
- Галерея, фильтры по дню и типу, личное избранное со звёздочками, просмотр и скачивание оригиналов. Автор может изменить отображаемое название кадра; оно хранится отдельно от имени оригинала и сохраняется при синхронизации. Кнопка «Наверх» возвращает к хедеру и началу ленты. MP4/WebM/Ogg воспроизводятся, если браузер поддерживает кодек. Остальные форматы скачиваются; для неподдерживаемых браузером фото показывается превью Диска.
- Карта OpenStreetMap / Leaflet. GPS из EXIF JPEG, HEIC/HEIF и PNG и ручные координаты автора. Рядом с кадром автоматически предлагаются места из Wikipedia; автор или владелец подтверждает место, после чего сохраняются краткое описание и ссылка на источник.
- Дневник поездки с записями по дням.
- Гостевой просмотр без регистрации по секретной ссылке: опубликованная галерея, карта, места и дневник всей поездки. Ссылка может быть заменена или отозвана. Приглашение участника и гостевая ссылка — разные разрешения.

## Даты и медиа

Дата определяется в порядке: EXIF DateTimeOriginal JPEG → дата EXIF Диска → photoslice_time Диска → дата создания файла на Диске. Последний вариант явно помечен в карточке как дата загрузки. Если метаданные неверны, файл может попасть в другой день; для MVP ручное исправление даты не реализовано. Границы участия — включительные календарные даты.

JPEG читается для EXIF ограниченным диапазоном до 512 KiB в оперативной памяти. Оригинал не записывается на сервер. Другие фото и видео индексируются по метаданным Диска; автоматическое чтение GPS из HEIC и видео в этот MVP не входит. Координаты можно указать вручную. Снимки без GPS доступны в галерее и не создают точки на карте.

Оригиналы и превью передаются потоком из Диска через сервер с проверкой доступа; поддерживаются Range-запросы для видео. URL и OAuth-токены Диска не раскрываются клиенту. HTTP-кеширование ответов с медиа отключено. Успешно загруженные превью фотографий и видео отдельно сохраняются в Cache Storage браузера, раздельно для пользователей и гостевых ссылок; версия файла входит в ключ кеша. При выходе из приложения кеш превью очищается. Оригиналы и видеопотоки в это хранилище не записываются. Лента использует ограниченное окно прокрутки: показывает видимые ряды плюс по одному ряду сверху и снизу. При движении вниз и вверх окно сдвигается по архиву с компенсацией позиции; высота страницы не растёт вместе с просмотренной историей. Ранее показанные карточки остаются смонтированными, но скрываются через display: none, поэтому при возврате используются те же элементы изображений без пересоздания. Загрузка превью идёт параллельно с приоритетом видимых кадров; соседние ряды используют не более двух фоновых загрузок. При смене окна ненужные запросы отменяются до Яндекс Диска, освобождая место текущему экрану. Сохранённые превью повторно читаются из браузера; при очистке или вытеснении кеша браузером они загружаются заново. Проигрывание конкретного видео зависит от браузера и кодеков; перекодирования нет.

Ссылка для гостя намеренно даёт доступ ко всей опубликованной поездке. Её следует передавать тем, кому разрешён такой просмотр. Приложение не гарантирует запрет сохранения уже открытого файла.

## Проверки

```powershell
npm run typecheck
npm test
npm run test:e2e
npm run build
```

Браузерный тест использует установленный Microsoft Edge, отдельный порт 3101 и отдельную базу data/e2e.sqlite. Тесты API создают отдельные базы data/test-*.sqlite. Пользовательская база не заполняется тестовыми поездками.

Проверяются регистрация, пароли, дата доступа, прямые запросы оригиналов, авторство, CSRF, одноразовость приглашений, отзыв ссылки, выход, шифрование токенов, OAuth state/PKCE и callback, сохранение прав Диска после повторного входа, одобрение папок, границы сканирования, идемпотентность, сбои синхронизации, Range и подтверждение мест. Браузер: регистрация → поездка → дневник → гостевой просмотр → отзыв ссылки; фильтры галереи, карта и мобильная ширина.

## Развёртывание

```powershell
npm ci
npm run build
npm start
```

Сайт и фоновая синхронизация стартуют вместе. Для отдельного процесса есть npm run worker; не нужно запускать его дополнительно, если используется npm start или npm run dev. Альтернатива — внешний планировщик каждые 15 минут вызывает POST /api/cron с Authorization: Bearer <CRON_SECRET>. Секрет не передавайте браузеру.

Для доступа друзей нужен постоянно работающий Node-сервер с диском для SQLite, домен и HTTPS. В .env.local смените APP_URL, зарегистрируйте соответствующий callback в Яндексе и настройте reverse proxy к 127.0.0.1:3000. Не используйте эфемерную файловую систему serverless-платформы. Установите все зависимости: рабочий процесс использует tsx. Потоки оригиналов проходят через сервер, поэтому учитывайте исходящий трафик и время запросов reverse proxy.

Сохраняйте резервную копию SQLite штатным механизмом SQLite backup и TOKEN_ENCRYPTION_KEY отдельно; без прежнего ключа сохранённые OAuth-токены не расшифровать. В SQLite нет файлов оригиналов. Не копируйте работающий файл базы без учёта WAL.

## Автозаполнение новой поездки по фотографиям

В форме создания можно сразу выбрать папку своего подключённого Диска. Два независимых флажка включают определение дат и направления. Начало и окончание — минимальная и максимальная дата съёмки среди фото в выбранной папке и подпапках; дата загрузки не используется. При неполных метаданных форма сообщает, сколько снимков имеют дату. При отсутствии дат или GPS остаётся ручной ввод с пояснением под полем.

Место предлагается по ближайшим населённым пунктам (в пределах 35 км) из локального справочника GeoNames / cities.json. Это приблизительное направление, а не точное распознавание маршрута; его нужно проверить. Названия городов в справочнике могут быть на латинице. Координаты для этой функции не отправляются геокодерам. Источники и лицензия: [GeoNames](https://www.geonames.org/) и [cities.json](https://github.com/lutangar/cities.json), CC BY 4.0; в UI указана атрибуция. Названия дедуплицируются в порядке съёмки, показываются до пяти городов.

Ручное изменение места выключает соответствующий флажок; изменение одной из дат выключает автоопределение дат. Значения сохраняются для исправления. Папка и новая поездка сохраняются одной транзакцией после проверки доступа. После создания фотографии больше не изменяют период поездки. Новый источник подхватывается фоновым процессом в течение ближайшего прохода (проверка новых источников каждые 30 секунд, повторная синхронизация источника — раз в 15 минут).

Анализ выполняется только по запросу пользователя: максимум 5000 фото, 2000 страниц списка или 5 минут. При превышении лимита приложение предлагает выбрать меньшую папку и не подставляет частичный результат. GPS автоматически читается из JPEG; другие изображения используют доступные метаданные Диска для дат. Кеш EXIF содержит только метаданные, без оригиналов и временных URL.

## Язык, оформление и проверка состояния

В шапке есть кнопка RU/EN и переключатель светлой/тёмной темы. «Авто» следует системному оформлению. Выбор сохраняется в браузере. Локализованы интерфейс, формы, ошибки, подписи кнопок и формат отображения дат. Собственные названия поездок, записи и исходные описания мест сохраняются на языке автора. Шрифты Golos Text и Lora загружаются из установленных пакетов, без Google Fonts.

Проверка базы и настроек: npm run health. Выводит только техническое состояние и количества записей, без email, паролей, ключей и содержимого заметок. Резервная копия: npm run backup; копия создаётся SQLite backup API в data/backups, совместимо с WAL. Ключ TOKEN_ENCRYPTION_KEY сохраняйте отдельно от копии базы.

В тестах e2e/design.spec.ts проверяются обе темы и языка, сохранение настроек, системная тема, увеличение текста до 200%, управление диалогом с клавиатуры, сценарии владельца, участника и гостя. Axe проверяет правила WCAG 2 A/AA и WCAG 2.1 AA на входе, формах, галерее, карте, дневнике и настройках. Автоматические проверки не заменяют ручную проверку с реальными медиа и ассистивными технологиями.

## Оформление

Светлая тема — Cobalt Clear, тёмная — Night Quest. Общие цвета, размеры и радиусы заданы в app/theme.css. Фирменный акцент — #3448F5, тёмный акцент — #A5AFFF. Шрифт Onest Variable хранится локально в зависимости @fontsource-variable/onest. Выбор темы и языка сохраняется между посещениями.

Автоопределение периода учитывает фото и видео. Если в папке даты из разных лет с разбросом больше 180 дней, приложение просит проверить период вручную; год не исправляется автоматически. EXIF-день сохраняется по календарной дате камеры без сдвига часового пояса сервера.

Названия городов и стран в автоматически определённом маршруте следуют языку RU/EN. Локализованные названия GeoNames загружаются из встроенного справочника; между маршрутом и странами используется `||`. Переключение языка не требует повторного чтения фото и не изменяет вручную введённое направление. Источники и обновление справочника описаны в lib/data/README.md.

Подтверждённые места: у одного кадра может быть несколько достопримечательностей. Расстояние проверяется по координатам выбранной статьи в радиусе 2 км; после подтверждения в просмотре кадра отображаются название, расстояние и краткое описание. Старые записи перенесены в confirmed_places с сохранением исходной таблицы places. Просмотр фотографий использует кешированное превью, включая HEIC; сбой загрузки оригинала не убирает доступное превью.

Карта: основной слой Esri World Street Map, резервный OpenStreetMap. Для запросов тайлов используется Referrer-Policy: origin, чтобы соблюдать требования провайдера и не передавать параметры ссылки поездки. Под основной картой расположена горизонтальная лента миниатюр с загрузкой только соседних кадров и общим кешем превью галереи.

## Профиль и друзья

Мой профиль находится на /profile, публичная страница — /@username, информация о проекте — /about. Друзья отображаются на главной странице и в собственном профиле. Заявку подтверждает получатель; её можно отменить/отклонить, дружбу — удалить. Список и заявки доступны только владельцу. Дружба сама по себе не открывает поездки: для этого остаются отдельные приглашения и гостевые ссылки.

Для тестов npm test использует scripts/test-env.mjs с уникальной SQLite и фиктивными ключами, без .env.local. Неподменённые внешние fetch запрещены. Браузерные тесты запускают отдельный Next-стенд3101 без worker, с новой БД, NODE_ENV=test, отдельным .next-e2e и блокировкой запросов к внешним провайдерам. Секреты не передаются стенду. Это регрессии функциональности, не сертификат безопасности развёртывания.

Подготовка к публичному запуску описана в docs/SECURITY.md.
